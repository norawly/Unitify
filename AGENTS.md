# Unitify: работа с репозиторием

## Контекст

Статический сайт расписания AITU + Cloudflare Worker, Telegram, D1,
Durable Object Ticker и Chrome MV3 Unitify Bridge. Это не React/Vite/Next.js.
Читайте `README.md`; для передачи — `docs/self-hosting.md` и `docs/agent-handoff.md`.
Актуальный код важнее исторических описаний.

## Границы

- Независимый экземпляр адаптируется в копии получателя. Не меняйте рабочие
  домен, токен, D1, регистрацию и владельцев автора ради переноса.
- Доступ рассчитан ровно на двух владельцев. Замены `MAX_USERS`/`REGISTRATION` недостаточно.
- `worker/access.js:retireOtherUsers` содержит историческую рассылку и удаление
  с проверкой `nurali`/`nurbek`. Не запускайте её на чужой/импортированной базе ради настройки.
- Не переносите секреты, владельцев, учебные данные и демодоступ автора.
  Пустая/некорректная конфигурация доступа должна закрывать вход.
- Нурали разрешил получателю использовать Unitify Bridge. Для установки ZIP
  не нужен новый item Google. Фиксированный backend текущей версии требует
  согласованной замены адресов для отдельного сервера.
- Не заявляйте о публикации/одобрении магазина без актуального подтверждения.
- `hidden`/`private` — не HTTP-защита статики; в `public/` не должно быть ключей или учебной базы.

## Исходники

- Расписание: `public/<slug>/schedule.js`; шаблон: `tools/page.html`.
- `npm run build` генерирует HTML, manifests, JSON, изображения и ZIP.
  Проверяйте diff: часть результатов отслеживается Git, часть игнорируется.
- При удалении профилей сначала разрешите `aliasOf` и проверьте старые
  сгенерированные файлы. Сборка не является универсальной очисткой каталога.
- Адреса backend: `wrangler.jsonc`, `extension/background.js`, `popup.js`,
  `manifest.json`; подписи/ссылки также в генераторах и политике приватности.
- Сохраняйте ограничения чтения Moodle, привязку к аккаунту, запрет записей,
  паузу во время тестов, backoff и обработку частичных данных.
- Не угадывайте соответствие предметов и статусы. Неизвестное не равно пропуску.

## Проверка и документация

- `npm ci`, локальный Wrangler, текущий lockfile.
- `npm test`: требуется Node.js с `node:sqlite`.
- `npm run build`: Python 3, современный Node.js, системный `zip`.
- Для развёртывания — dry-run, затем проверка аккаунта и целевых ресурсов.
- D1: явно разделяйте `--local` и `--remote`, применяйте все миграции.
- Секреты вводятся интерактивно; `.dev.vars` не публикуется автоматически.
- Проверяйте вид результата после визуальных изменений.
- Разделяйте локальные тесты, облачную публикацию, реальный Moodle и реальное устройство.
- Обновляйте README и инструкции передачи при изменениях доступа/API/расширения.
  Не описывайте запланированное как реализованное.
