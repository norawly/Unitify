# Промпт для ИИ-агента получателя

Передайте агенту репозиторий и весь текст ниже. Полный технический маршрут
находится в `docs/self-hosting.md`; он входит в репозиторий и обязателен к чтению.

---

Ты получил Unitify (ранее JustSchedule / Schedule) — учебный помощник AITU.
Разверни для меня полностью самостоятельный экземпляр в моём Cloudflare:
сайт расписания/PWA, карту, Telegram-бота с напоминаниями и Moodle-интеграцией,
D1, Durable Object Ticker и Unitify Bridge.

Нужен работающий результат, а не только план. Изучи репозиторий, адаптируй
необходимые места в моей копии, проверь их и доведи установку до конца.
Обычные обратимые решения принимай самостоятельно. Запрашивай только мои данные,
вход и действия, без которых продолжение невозможно. Секреты вводятся защищённо,
не через переписку.

**Про расширение:** Нурали явно разрешил мне использовать его Unitify Bridge.
Не создавай новый item Chrome Web Store и не требуй заново публиковать расширение
в Google. Используй существующие исходники, собери ZIP для моего backend и помоги
установить распакованную копию через `chrome://extensions`.
Это то же расширение, адаптированное к моему адресу сервера.

Не обещай, что установленный пакет с фиксированным сервером Нурали автоматически
подключится к моему Cloudflare: в текущей версии нет выбора backend.
Не отправляй мои данные на его сервер. Если потребуется именно магазинная версия,
объясни необходимость поддержки нового адреса в обновлении существующего item
его владельцем; не выдумывай, что такое обновление уже опубликовано.

Контекст и порядок действий:

1. Прочитай `AGENTS.md`, `README.md`, **весь `docs/self-hosting.md`**,
   `extension/README.md`, `docs/demo-access.md`, конфиг, package/lockfile,
   код доступа, cron, DB, API расширения, миграции и тесты.
   При расхождении следуй текущему коду. Документация актуализирована 27.10.2026.

2. Стек: обычные HTML/CSS/JS; один Cloudflare Worker с Static Assets,
   D1 `DB`, SQLite Durable Object `TICKER` класса `Ticker` и резервным
   минутным cron. GitHub Pages — только отдельная статика, не замена серверу.
   Не переписывай проект на другой стек.

3. Создай отдельный экземпляр в моём аккаунте, с новым Worker, новой D1 и
   новым Telegram-ботом. Сначала `workers.dev`, собственный домен опционален.
   Не меняй production, токен, webhook, базу и доступ исходного владельца.
   Не импортируй его учебные данные и не используй его демонстрационный доступ.

4. **До запуска адаптируй закрытый доступ на одного реального владельца.**
   Исходный код требует ровно двух ID; одна переменная `MAX_USERS` это не исправляет.
   Проверь `access.js`, `db.js`, `cron.js`, `lms-extension.js`, все проверки
   количества ID и SQL с двумя параметрами. Сохрани отказ посторонним и при
   некорректной конфигурации. Не используй фиктивный второй аккаунт.
   Историческую `retireOtherUsers`, привязанную к `nurali`/`nurbek`,
   исключи из новой установки или безопасно адаптируй: никаких старых рассылок,
   удаления моих данных и обязательных записей автора.
   Обнови тесты под новую модель, не удаляя проверки безопасности.

5. Подготовь мой профиль `public/<slug>/schedule.js`: имя, непустой баркод,
   группа, реальные занятия и академические даты. Slug — `[a-z0-9-]`,
   1–40 символов. Если моих данных нет, запроси их и обозначь заготовку.
   Не выдумывай занятия. Проверь зависимости `aliasOf`; исключи старые
   персональные профили и остатки генерации из публикуемой копии.
   `hidden`/`private` не защищают статические URL; не клади личную базу в `public/`.

6. Подготовь окружение: современный Node.js с `node:sqlite`/`import.meta.dirname`,
   npm, Python 3 и `zip`. `npm ci`, текущий lockfile и локальный Wrangler.
   В исходном проекте локально прошли 79 тестов, но после твоей адаптации
   требуются новые результаты. Не утверждай, что облако проверено этими тестами.

7. В `wrangler.jsonc` замени имя, D1 UUID/имя, `PUBLIC_URL`, контакт и лимиты.
   Удали route `s.zhengisbay.com`; для первого запуска включи `workers_dev`.
   Сохрани Assets, worker-first маршруты, D1 binding, Ticker с SQLite migration,
   cron и ограничения частоты. Проверь аккаунт через `wrangler whoami`.
   Создай свою D1, примени все миграции локально и удалённо. Два файла
   с префиксом `0005` нужны оба. Не обещай бесплатную работу без проверки тарифа.

8. Согласуй backend расширения с фактическим origin:
   `extension/background.js` API, `extension/popup.js` update URL,
   `extension/manifest.json` server permission/homepage, публичная политика,
   ссылки/подписи генераторов. Moodle-хост AITU остаётся прежним.
   Пересобери `public/downloads/unitify-moodle-reader.zip`.
   Отдельная публикация Google не нужна. Передай мне ZIP без ключей и данных.

9. Выполни `npm run build`, `npm test`, `npx wrangler deploy --dry-run`,
   затем деплой выбранного собственного Worker.
   Команды создания и миграций, точная последовательность и проверки —
   в `docs/self-hosting.md`. Не используй реальные токены в локальных
   тестах так, чтобы менять рабочий webhook или отправлять лишние сообщения.

10. Помоги мне создать нового бота через BotFather и безопасно установить
    `TELEGRAM_TOKEN`, `BOT_ALLOWED_CHAT_IDS`. Мой числовой ID нужен до регистрации;
    исходная `/id` не является единственным bootstrap-способом.
    На моём origin вызови `/tg/setup`, проверь `/tg/status`, webhook и Ticker.
    Webhook-секрет вычисляется из токена; отдельного обязательного
    `WEBHOOK_SECRET` в текущем коде нет.
    Пройди `/start` → мой баркод → администратора/владение профилем.
    Проверь отказ посторонним. Первый вошедший не должен быть случайным человеком.

11. Установи мне ZIP: распаковка в постоянную папку, режим разработчика Chrome,
    «Загрузить распакованное», код `/extension` своего бота (10 минут).
    Используй чистую установку, не переноси device token/хранилище автора.
    Проверь фактические запросы pairing и sync на мой сервер.
    Распакованная версия обновляется заменой файлов и кнопкой ↻, не автоматически.

12. Moodle имеет два канала: личный iCalendar с `authtoken` для серверных
    календарных дедлайнов и расширение для заданий/оценок/attendance через мою
    авторизованную сессию. Реальный вход выполняю я.
    Пароли, cookies, HTML и файлы работ не передаются; не автоматизируй запись
    в Moodle, сдачу работ и отметки attendance. Сохрани политику чтения,
    паузы, интервал, Retry-After, изоляцию аккаунта и частичное сохранение.
    Без браузера бот читает сохранённую базу; новые оценки сами не появляются.

13. Проверь сайт визуально на настольной и мобильной ширине, карту, темы,
    свайпы и статистику; Telegram-команды, постоянную клавиатуру и карточки;
    реальное контрольное напоминание, pairing, синхронизацию и отзыв доступа.
    Unknown attendance не равен пропуску; прогноз не гарантия.
    PWA и настоящий телефон проверяй отдельно.
    Не обещай работу настольного расширения в Safari на iPhone.

14. Обнови документацию моей копии под фактическую конфигурацию.
    Передай адрес сайта, username бота, ZIP расширения, инструкцию изменения
    расписания/обновления/резервного копирования D1 и список проверок.
    Раздели локальные тесты, публикацию, настоящий Moodle и устройство.
    Если мой вход пока недоступен, подготовь всё остальное и укажи точное
    оставшееся действие. Не называй перенос завершённым без нужных проверок.

Начни с короткого аудита зависимостей от автора, затем выполняй перенос
по `docs/self-hosting.md`. Мой целевой вариант — самостоятельный Cloudflare
и использование уже разрешённого Unitify Bridge, без новой публикации в Google.
