# Закреплённый демонстрационный доступ

Основные владельцы остаются в `BOT_ALLOWED_CHAT_IDS` (ровно два ID).
Приглашённые зрители задаются отдельным серверным секретом `BOT_DEMO_ACCESS`:

```json
{"source":101,"viewers":[303,404]}
```

Числа в примере вымышленные. `source` должен быть одним из двух владельцев,
`viewers` — от одного до двух отдельных Telegram ID. Значения не хранить в Git.
Для каждого зрителя оператор создаёт строку `users` со статусом `approved`;
регистрация остальных пользователей остаётся закрытой. Владение в `owners`
не изменяется и не передаётся зрителям.

Зритель читает актуальные записи источника без копирования Moodle-ссылки,
ключей расширения или учебной базы. Сообщения, лимит запросов, очистка чата и
курсор уведомлений у каждого свои. Календарь Moodle проверяется только у
источника: для зрителей не создаются дополнительные Moodle-запросы.

Недоступны смена расписания/языка/напоминаний, привязка и отключение календаря
или расширения, ручные отметки о выполнении заданий, административные действия.
Настройки объясняют закреплённый доступ и показывают контакт разработчика.
Начальный экран и приветствие явно обозначают демонстрацию чужих данных.

Отключение `BOT_DEMO_ACCESS` или удаление ID из его списка немедленно
закрывает вход и исключает зрителя из фоновых рассылок. Академические данные
не требуется удалять у зрителя: они всегда остаются у источника. Отдельно можно
удалить его собственную строку `users`, записи `msgs`/`sent` и служебный курсор
`meta` с ключом `demo-lms-cursor:<viewer ID>` по точному ID.

Получатель видит настоящие учебные данные владельца и может сохранить их у
себя в Telegram. Выдавать этот доступ только по явному согласию владельца.
